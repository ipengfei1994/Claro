# 已知限制（Known Limitations）

这份清单只写**实际验证过的事实**。凡是"没跑过""没装""没连过真实端点"的，都明确写在这里，而不是在别处含糊带过。

## 1. 环境与基础设施

| 限制 | 影响 | 现状 |
|---|---|---|
| Hive / Hadoop / Beeline 未安装 | 离线数仓链路（ODS→DWD→DWS→ADS）无法执行 | SQL 与导出器已实现，`claro warehouse-export` 可生成 CSV/SQL；执行器会明确失败，不伪造成功 |
| 单机单节点 Kafka（KRaft，副本数 1） | 无副本、无 ACL/TLS、无跨机房容灾 | 开发与演示足够；生产需多副本与安全协议 |
| PostgreSQL 单实例，无流复制 | 无高可用、无读写分离 | 备份靠 `pg_dump`；未做过故障切换演练 |
| Redis 单实例（Windows 分支版） | 无哨兵/集群，重启后缓存全冷 | 缓存不可用时自动回落 PostgreSQL |
| 未做容器化 | 不支持 `docker compose up` | 这是项目的**明确约束**，全部走 Windows 原生服务 |

## 2. 身份与安全

| 限制 | 说明 |
|---|---|
| 身份是**模拟**的 | 侧栏"审核身份"只是切换一个字符串，没有登录、会话、密码，任何角色都能执行全部操作。界面已标注"模拟身份认证，非生产级登录" |
| 无 RBAC 强制 | 角色字段（moderator / senior_moderator / admin / auditor）只进入审计记录，不参与授权判断 |
| 无 API 网关与限流 | Streamlit 直连数据库；限流只存在于业务层（`check_rate_limit`）与处置策略 |
| 审计不可篡改，但未做签名 | `audit_event` 是追加式的，应用层不提供删除入口；数据库层面没有防篡改（没有链式哈希或外部存证） |

## 3. 检测能力

| 限制 | 说明 |
|---|---|
| 语义检测器是**占位** | 当前返回"不可用"状态，不产出任何分数；融合层在缺层时按剩余层归一化 |
| LLM 顾问层默认关闭 | 未对真实端点做过调用验证；测试只用伪造传输。启用需要 `CLARO_RISK__LLM__BASE_URL` 与 `API_KEY` |
| ML 模型训练于合成数据 | char_wb TF-IDF + 逻辑回归，指标（P/R/F1）来自合成模板文本，**不可外推到真实游戏语料** |
| 模型产物默认不入库 | `models/` 被 `.gitignore` 忽略；没有模型文件时 ML 层静默缺席（详见 `RISK_INTELLIGENCE.md`） |
| 类别体系固定 19 类 | 新增类别需要改 YAML + 重新训练，没有在线学习 |

## 4. 治理与处置

| 限制 | 说明 |
|---|---|
| 处置动作**模拟执行** | 禁言、封禁写入本地 `player_enforcement_state` / `enforcement_action`（`simulated=true`），**不会下发到任何游戏服务器** |
| 无真实工单系统对接 | `moderation_case` 是内置的轻量状态机，不与外部客服/工单平台同步 |
| 审核 SLA 只是字段 | `due_at` 会计算并显示逾期，但没有提醒、升级通知或自动分派 |
| 策略条件为声明式白名单 | 支持关键词/正则/阈值/类别/玩家/服务器/联盟/黑白名单/限流/组合；**不支持任意 Python 表达式**（这是有意的安全限制） |
| 正则未做复杂度静态检查 | 规则来自受控 YAML，不是用户输入；但没有 ReDoS 检测器，写坏的正则仍可能拖慢检测 |

## 5. 数据与分析

| 限制 | 说明 |
|---|---|
| 数据是**合成**的 | 所有指标只证明链路正确，不代表线上效果 |
| 时间分布不均匀 | `risk_event` 集中在 2026-01–02，消息集中在年初与演示日；总览默认"近 1 年"才能看到全貌 |
| 50,003 条历史决策无 `decision_status` | Phase 02 遗留数据；`自动处置率` 只统计有状态的 15 条，界面口径已注明 |
| 自动处置率 / 人工审核率常显示"不可计算" | 分母 < 30 时主动抑制，这是设计行为，不是缺陷 |
| 2026-11 之前几乎没有人工审核与反馈 | `moderation_review` / `governance_feedback` 主要由演示流程产生，容量很小 |
| 报告导出只有 Markdown + CSV | Excel / PDF 无依赖实现，未做 |

## 6. 界面

| 限制 | 说明 |
|---|---|
| 单页应用，无前端路由权限 | 所有页面共用同一个 `AppContainer` 缓存连接池 |
| 导航超过 10 项会折叠 | 15 个页面分 5 组，Streamlit 会折叠为"View 5 more"，这是框架行为 |
| 图表是 Plotly 默认交互 | 没有自定义下钻与联动筛选；跨图联动需要重新查询 |
| 仪表盘数据最多滞后 45 秒 | 纯读聚合走 45 秒缓存（`claro/ui/cache.py`），侧栏"刷新数据"可立即清空。写入类页面不缓存，写完即读到的就是新值 |
| 首次加载较慢 | 清空缓存后，分析总览首次渲染约 7.0 s、治理总览约 4.9 s（50,016 条消息）；缓存命中后 0.6–1.1 s |
| 未做移动端适配 | 目标场景是桌面宽屏；窄屏下表格需要横向滚动 |
| 无国际化 | 界面为中文，代码与文档注释为英文/中文混排 |

## 7. 工程

| 限制 | 说明 |
|---|---|
| 批量入库吞吐有限 | 实测 62–81 行/秒（单条事务路径，两轮基准的区间）。大批量回填需要等待；已在 `PHASE_06_PERFORMANCE.md` 中量化并说明瓶颈 |
| 无 CI 流水线 | 测试靠 `scripts\run_tests.ps1` 本地执行；未接入 GitHub Actions（Windows 原生依赖较重） |
| 无容器化测试矩阵 | 只有本机 Python 3.12 + PostgreSQL 18.3 的组合 |
| 无压力测试 | 只做了单进程串行基准，没有并发用户模型 |
